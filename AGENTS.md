Ты работаешь внутри кастомного модуля AzerothCore для WoW WotLK 3.3.5a.

Твоя задача — изучить именно этот custom module и создать для него:

1. подробный проектный контекст;
2. project-specific Codex skill;
3. резервную копию skill в docs;
4. правила `.gitignore` для созданных артефактов.

Не изменяй игровую логику модуля, если это не требуется отдельно. На этом этапе нужно только исследовать проект и создать документацию/skill.

Отвечай на русском языке.

# 1. Область исследования

Исследуй текущий custom module относительно AzerothCore и определи:

- название модуля;
- какую игровую механику он добавляет;
- какие проблемы решает;
- какие части AzerothCore использует;
- какие hooks, scripts и handlers регистрирует;
- какие базы данных используются;
- какие SQL-таблицы создаются и изменяются;
- какие команды игрока, GM или консоли добавляются;
- какие конфигурационные параметры поддерживаются;
- есть ли клиентский addon;
- есть ли серверно-клиентский протокол;
- какие события WoW/AzerothCore обрабатываются;
- какие данные сохраняются между сессиями;
- какие миграции выполняются;
- какие есть ограничения, риски и технический долг.

Обязательно изучи:

- `src/`;
- `include/`;
- `conf/`;
- `data/sql/`;
- `scripts/`, если существует;
- клиентский addon, если он есть;
- `CMakeLists.txt`, `include.sh`, `conf.sh`, loader-файлы и другие build-интеграции;
- `README.md`;
- существующие `AGENTS.md`;
- `.agents/`, `.codex/`, если доступны;
- git history и последние изменения, если это помогает понять архитектуру.

Используй код как источник истины. Не выдумывай поведение, которое не подтверждено исходниками.

# 2. Особенности AzerothCore

Отдельно зафиксируй интеграцию модуля с AzerothCore:

- `WorldScript`;
- `PlayerScript`;
- `UnitScript`;
- `CreatureScript`;
- `GameObjectScript`;
- `SpellScriptLoader`;
- `AuraScript`;
- `CommandScript`;
- `GlobalScript`;
- `MapScript`;
- `AllMapScript`;
- `BattlegroundScript`;
- `GuildScript`;
- другие зарегистрированные ScriptMgr-классы.

Для каждого класса укажи:

- имя;
- файл;
- метод-хук;
- когда он вызывается;
- какие данные изменяет;
- есть ли ограничения по потоку/сессии;
- есть ли риск повторного вызова;
- какие другие компоненты зависят от этого поведения.

Опиши:

- точку входа loader-а;
- порядок регистрации скриптов;
- требования к версии AzerothCore;
- зависимости от core API;
- зависимости от существующих таблиц AzerothCore;
- зависимости от worldserver/characters database;
- нужен ли authserver;
- нужен ли отдельный NPC, GameObject, spell или item template.
